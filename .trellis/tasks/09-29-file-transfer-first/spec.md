# PasteBox：文件中转优先的界面与分享能力

## Problem Statement

用户希望把 PasteBox 从偏在线剪贴板的使用方式调整为文件中转优先：打开即可发送或接收文件，跨设备领取不依赖复制长链接，一次发送多个文件有清晰进度与记录，时效、隐私和领取限制在主流程中可见。

现有游客入口已有文本、图片和文件模式，但登录工作区体验尚未统一；分享已有密码、有效期及次数限制，这些不等于短取件码、一次领取会话或真正的内容销毁。仅改文案会使界面承诺与实际能力不符。

调研的站点自然搜索流量对比支持文件中转优先的产品方向，但不是精确关键词搜索量、转化率或获客保证。

## Solution

保留 Clay 风格、文本与图片能力，以“发文件 / 取文件”为主入口，默认发送文件。将多文件视作一份传输，全部上传成功后生成分享链接和 6 位取件码。用户在发送区设置有效期、密码、登录限制及独立的阅后即焚选项。

阅后即焚支持 1 或 N 个匿名领取名额，界面使用“可领取次数”，不声称识别独立自然人。领取后的一次文件会话允许逐个下载与失败重试。跨设备自动更新记录、领取及失效状态，展示真实连接状态。容量与能力文案来自实际配置，老分享链接继续可用。

## User Stories

1. 作为首次访问者，我希望首屏直接显示文件发送入口，以便不经过营销页面就开始操作。
2. 作为发送者，我希望默认选择文件模式，以便主要操作符合文件中转定位。
3. 作为文本用户，我希望切换到文本模式，以便继续使用原有文本分享能力。
4. 作为图片用户，我希望切换图片模式，以便快速分享图片。
5. 作为接收者，我希望有独立的取文件入口，以便无需寻找发送表单中的隐藏功能。
6. 作为发送者，我希望点击选择或拖入多个文件，以便一次完成一批文件的准备。
7. 作为发送者，我希望一批文件归为一份传输，以便只发送一套分享凭据。
8. 作为发送者，我希望看到逐文件上传进度，以便了解哪些文件仍在上传。
9. 作为发送者，我希望只重试失败的文件，以便不重复上传成功项。
10. 作为发送者，我希望文件全部上传成功后才发布分享，以便接收者不会拿到不完整清单。
11. 作为接收者，我希望看到文件清单并逐个下载，以便选择需要的文件。
12. 作为发送者，我希望在主输入区旁设置有效期和隐私选项，以便不用跳出发送流程。
13. 作为发送者，我希望密码和登录限制对链接与取件码同样有效，以便权限不因入口不同而失效。
14. 作为发送者，我希望阅后即焚是独立且默认关闭的开关，以便明确选择是否销毁内容。
15. 作为发送者，我希望开启销毁前看到范围和触发条件，以便避免误删。
16. 作为发送者，我希望设置 1 或 N 次匿名领取，以便一份传输可供一位或多位接收者使用。
17. 作为发送者，我希望界面说明次数不等于独立人数，以便理解匿名领取的限制。
18. 作为接收者，我希望仅打开页面不会占用名额或触发销毁，以便先确认操作。
19. 作为文本接收者，我希望主动查看后才消费一次领取，以便避免预加载误触发。
20. 作为文件接收者，我希望主动领取后获得独立会话，以便逐个下载同批文件。
21. 作为文件接收者，我希望会话内下载和失败重试不重复扣次数，以便一次领取覆盖完整传输。
22. 作为文件接收者，我希望看到最长 30 分钟且不超过分享有效期的领取窗口，以便及时下载。
23. 作为文件接收者，我希望能主动完成领取，以便结束本次访问。
24. 作为后续接收者，我希望前一位领取结束后仍能使用剩余名额，以便多人分享正常工作。
25. 作为发送者，我希望销毁同时覆盖内容和附件，而非仅隐藏链接，以便时效承诺真实有效。
26. 作为发送者，我希望知道物理清理在后台进行且不影响接收者已保存副本，以便理解销毁边界。
27. 作为发送者，我希望成功页突出复制链接、取件码和有效期，以便快速转发。
28. 作为跨设备接收者，我希望输入 6 位数字字母取件码，以便不必复制长链接。
29. 作为接收者，我希望取件码避开易混淆字符且不区分大小写，以便减少输入错误。
30. 作为接收者，我希望也能粘贴分享链接，以便沿用熟悉的接收方式。
31. 作为发送者，我希望撤销或过期同时使链接和取件码失效，以便控制整份分享。
32. 作为用户，我希望错误取件码有一致提示且高频尝试受到限制，以便降低猜码风险。
33. 作为已有用户，我希望老分享链接保持可用，以便升级不破坏已发出的分享。
34. 作为游客，我希望在既有容量和保留期限内发送、取件，以便不因本次升级强制注册。
35. 作为登录用户，我希望传输记录按一次发送归组，以便回看和管理历史记录。
36. 作为登录用户，我希望原有内容管理功能保留，以便继续处理既有笔记和附件。
37. 作为同账号多设备用户，我希望传输记录、领取次数和失效状态自动更新，以便无需反复刷新。
38. 作为发送者，我希望成功页自动更新领取状态，以便了解文件是否已被领取。
39. 作为接收者，我希望页面更新可领取、已领完和已失效状态，以便减少无效操作。
40. 作为用户，我希望看到真实连接、重连和中断状态，以便区分内容未更新与网络中断。
41. 作为用户，我希望重连后获取最新状态，以便不依赖断线期间遗漏的事件。
42. 作为文本用户，我希望保存后同步且远端更新不静默覆盖未保存草稿，以便保留自己的编辑。
43. 作为游客，我希望状态访问仅限持有凭据的传输，以便保护其他人的内容。
44. 作为移动端用户，我希望上传、取件和设置在小屏上仍可操作，以便跨设备传文件。
45. 作为用户，我希望首屏容量、保留期、注册要求和限速说明符合实际配置，以便作出可靠选择。
46. 作为用户，我希望看到统一清晰的中文内容规范和举报提示，以便理解使用边界。

## Implementation Decisions

### 界面与兼容

- 调整首页、登录工作区、发送成功页、接收页、导航和站点描述，以文件中转为主叙事；保留 Clay 风格，不整页重写。
- 统一文件、图片、文本输入模式，默认文件；时效与隐私控件内联，阅后即焚独立展示。
- 首屏关键参数控制在四条以内，读取实际配置，不新增不限量、永久不限速或未经实现的加密承诺。
- 保留既有内容管理、老分享链接、游客与账号的权限和配额规则；历史分享不强制补码或改变销毁行为。

### 传输与发布

- 一份传输包含本次发送的文件集合，统一有效期和分享凭据。服务端核验上传完整后发布，不能只靠前端隐藏按钮。
- 复用现有内容、附件和分享模块，以必要的增量持久化表达批次、发布状态和领取状态。具体表结构与 API 路径在代码核验后确定，不把未经核验的接口当作既定契约。
- 失败项重试不重复创建成功附件；发布重试不重复创建传输。核验放弃上传的清理、配额释放与异常恢复。

### 取件码与授权

- 6 位数字与大写字母组合，避开易混淆字符，输入不区分大小写。
- 使用安全随机源、有效码唯一约束及冲突重试；具体字符集、限流阈值和码再分配策略由技术设计补齐。
- 链接与取件码定位同一份分享，密码、登录限制、有效期及撤销规则一致。错误提示统一，限制高频尝试，不新增公开枚举入口。

### 领取与销毁

- 可设置 1 或 N 个匿名领取名额，不引入指定账号或验证邮箱的接收人名单；既有分享登录限制仍生效。
- 主动查看文本或领取文件才消费名额；查看状态、页面预览、连接重建不消费名额。
- 名额分配在服务端原子执行，领取重试保持幂等；名额领完阻止新领取，但不提前结束已有有效会话。
- 一次文件领取会话覆盖同批文件，支持逐个下载和失败重试。会话在主动完成或最长 30 分钟后结束，且不超过分享有效期。
- 多人最终销毁采用待最终复核的汇总方案：全部名额已领取且全部会话结束后销毁；未领满则分享到期销毁。文本消费完全部名额后失效，不在第一位查看时删掉其他名额所需内容。
- 先使内容与附件不可访问，再后台物理清理。核验下载授权、对象存储直链和缓存，不能只禁用页面入口；清理失败可重试，不恢复访问权限。
- 销毁针对该传输，不扩展到无关内容。对已有内容开启破坏性分享时，必须清楚说明其影响范围；不承诺删除接收端副本。

### 状态同步

- 同账号多设备同步传输记录、领取次数和失效状态；发送成功页和接收页自动刷新相关状态。
- 展示服务端通信的真实连接状态，重连后读取权威最新状态；具体协议优先复用既有机制，尚未选定新依赖。
- 文本保存后同步，不做逐字协同编辑；保护未保存草稿，发生冲突时不得静默覆盖。
- 按账号或持有的传输凭据隔离状态访问，状态事件不代替鉴权，也不泄露未授权内容。

### 实施顺序

1. 核验并补齐传输发布、取件码、领取会话和销毁契约及持久化。
2. 实施文件中转界面、内联设置与文案，保留既有入口兼容。
3. 接入状态同步、权限隔离和重连恢复。
4. 完成回归、并发与浏览器验收，记录迁移和回滚边界。

## Testing Decisions

测试入口方案待用户核对，不将本次规格整理描述为测试已执行。

- **主要入口：现有 HTTP API 集成测试。** 复用 Go HTTP handler、测试请求客户端及断言方式，从公开请求到响应验证完整传输生命周期，不为每层新增 mock 或测试专用接口。
- 好测试断言用户可观察结果：已上传文件是否完整、领取是否扣次数、有效凭据能否下载、失效后是否拒绝访问；不绑定内部函数调用次序、私有字段或组件 DOM 层级。
- 测试模块覆盖上传与发布、链接/取件码分享、领取与销毁、同步授权；通过同一 HTTP 边界组合场景，尽量少增测试入口。
- 上传场景覆盖多文件部分失败、成功项不重传、重复发布、未完成上传禁止发布，以及游客和账号权限差异。
- 取件场景覆盖 6 位码、大小写、冲突、错误码、限流、密码与登录限制、过期、撤销及老链接兼容。
- 领取场景覆盖 1/N 名额、并发超额竞争、重复领取请求、预览不占位、同会话多文件下载与重试、会话结束、分享到期和名额耗尽后的已有会话。
- 销毁场景覆盖第一位领取不破坏剩余名额、全部会话结束后的不可访问、后台清理失败重试、已有下载授权边界。
- 同步场景覆盖用户/游客凭据隔离、断线重连补齐、失效事件、订阅不占名额、文本保存与未保存草稿保护。
- **必要的持久化补充：** 复用现有 PostgreSQL 跨连接并发测试先例，验证多连接原子领取及有效码唯一性；内存测试不替代真实数据库并发证据。现有数据库测试在未配置集成数据库时会跳过，必须单独报告。
- **后台清理补充：** 参考既有 worker 清理任务与失败退避测试，仅补 HTTP 入口难以观察的物理清理和重试结果。
- **浏览器验收：** 真实页面验证桌面/移动端发送、取件和失败恢复，双会话验证自动更新与权限隔离。核对界面与请求结果，不仅检查截图。
- 现有前端提供类型检查和构建命令，尚未观察到单独的前端单测命令；不把构建成功当成浏览器验收通过。

## Out of Scope

- 文件夹上传、打包下载、断点续传。
- 指定接收账号、接收邮箱身份验证、保证不同名额属于不同自然人。
- 逐字协同编辑、自动读取系统剪贴板、匿名共享房间。
- 新增永久网盘承诺、未经实现的端到端加密、无限容量或不限速承诺。
- 调整套餐定价、部署基础设施或替换整个前后端架构。
- 强制给历史分享补取件码，或默认开启历史内容销毁。
- 未经请求提交、推送应用代码或上线服务。本次 Issue 发布与代码发布是不同动作。

## Further Notes

- 本规格综合当前对话、产品调研、任务需求、五份 ADR 及领域术语表。6 位码、匿名名额和状态同步范围以用户明确选择为准。
- 多人最终销毁时机仍保留在最终复核项中，不因调用 to-spec 就伪称已得到单独批准。
- 推荐用现有 HTTP 集成测试作为主测试入口，以数据库并发、后台清理和少量真实浏览器场景补齐其盲区；发布前需用户核对这些入口。
- 用户已确认并完成项目技能配置：规格发布到 CVinit/PasteBox 的 GitHub Issues，使用 ready-for-agent 标签，不另行分诊。
- 用户已要求继续发布步骤；该发布不等于应用代码实施或上线，也不自动消除规格中注明的最终复核项。
- 本轮交付为规格文档，应用功能尚未实施、测试尚未执行。
