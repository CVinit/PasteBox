# 文件中转技术设计（实施前审阅稿）

关联 Issue： https://github.com/CVinit/PasteBox/issues/4

本轮只核验代码并设计，不启动应用代码实施。产品范围沿用 PRD、spec 与 ADR；下面新增接口和字段均为建议，不是现有能力。

## 1. 现状核验与关键差异

| 现有位置 / 符号 | 核验事实 | 对本任务的影响 |
| --- | --- | --- |
| `internal/app/models.go`：Paste、Share | Paste 已容纳多个附件；Share 有访问/下载计数，但无批次发布、领取名额和会话 | 复用内容与附件存储，新增领取语义，不把 MaxDownloads 当领取次数 |
| `web/src/App.tsx`：uploadFile | 上传优先使用 selectedPaste，缺省才创建内容 | 新发送必须绑定明确的新传输，不把文件误附到选中的历史笔记 |
| `internal/app/shares.go`：AccessShareWithContext | 打开分享即消费访问次数 | 新接收页的预览、状态查询必须与主动领取分离 |
| `internal/httpserver/server.go`：accessShare / downloadSharedAttachment | 先访问分享设置 Cookie，下载再检查 Cookie | 现有 Cookie 不是新的领取名额凭据 |
| 同文件：shareAccessCookieTTL | 现有分享访问 Cookie 为 15 分钟 | 不能直接复用为已约定的最长 30 分钟领取会话，也不能全局改老链接 TTL |
| `internal/app/attachment_streams.go`：OpenSharedAttachmentWithAccessGrantContext | 文件由对象存储流经服务端；扫描状态须 clean，下载受配额约束 | 新领取下载继续走服务端鉴权和流式输出，不新增裸对象直链 |
| `internal/httpserver/server.go`：writeDownloadStream | 当前 io.Copy 输出文件，返回不表示用户已保存成功 | 自动下载完成不是销毁依据，沿用显式完成领取/会话到期 |
| `internal/postgres/content_metadata.go`：ConsumeShareVisit / ConsumeShareDownload | 数据库事务和分享行锁处理计数，下载还更新日流量与附件计数 | 仿照事务边界实现领取，但保留下载流量计量，重试不扣名额不代表免流量 |
| `internal/app/content_stores.go` | 存在 typed stores、原子对象引用操作及跨进程对象锁 | 复用引用计数清理，不能按一个分享直接删除仍被其他内容引用的物理对象 |
| `internal/app/cleanup.go`：RunCleanup / cleanupPasteLocked | 已有清理流程、持久化清理协调与附件扫描任务 | 扩展现有 worker 清理，不另起独立常驻服务 |
| `web/src/App.tsx`：refreshAuthed | 当前可见刷新链路主要由页面进入/动作完成触发 | 新增状态通道；本次在前后端相关目录未检出 EventSource、WebSocket 或 SSE 处理器 |

数据库规范要求 PostgreSQL 为事实来源，HTTP handler 不写 SQL；已应用迁移不改，新增有序迁移。现有最大迁移版本为 000009，实际实施时重新检查后选下一个版本。

## 2. 模块与数据边界

建议在现有 app / postgres / httpserver 层内增加聚焦的 transfer 文件，不继续向大文件塞全部逻辑，也不进行无关整片拆分。

- **传输记录**：引用一条专属 Paste，持有创建者/游客归属、模式、发布状态、预期文件项、发布时间与幂等键。正文和对象数据继续由既有模块持有。
- **文件项**：用客户端稳定 item ID 对应附件，记录上传状态；成功项重试返回已有附件，内容不一致的同键请求返回冲突。并发上传/发布锁定同一传输，发布后冻结清单。
- **分享扩展**：关联传输、领取上限、已领取计数、阅后即焚标志。旧分享无传输关联时保持原路径与原语义。
- **取件码映射**：6 位码映射分享，唯一约束和安全随机生成。规范化大小写后查找；建议独立保存查询摘要并沿用现有秘密加密设施供发送者回显，不以普通日志记录码和令牌。
- **领取会话**：关联分享、凭据摘要、客户端领取操作 ID、创建/到期/完成时间；有效期取分享有效期和领取时间加 30 分钟的较小值。权威状态持久化，重启和跨实例不丢名额。
- **限制状态**：防猜码速率使用现有共享限流能力优先，实施前核验多实例路径；不得仅依赖进程内 map 宣称分布式保护。

不把公开取件码当发送者管理权限；游客管理凭据、接收状态权限、领取会话权限分开。只有持有领取会话才读取受限内容或下载，状态接口仅返回已授权的必要元信息。

## 3. 建议 API 契约

以下为新传输命名空间草案，实际路由落位时遵循已有前缀和错误结构。

| 操作 | 建议接口 | 核心约束 |
| --- | --- | --- |
| 创建批次 | POST /api/v1/transfers | 用户或游客鉴权，幂等创建，明确预期文件清单 |
| 上传一项 | POST /api/v1/transfers/{id}/items/{itemId} | 流式接收；复用限额、扫描、对象引用；相同项重试幂等 |
| 发布 | POST /api/v1/transfers/{id}/publish | 数据库内检查每项已完成、归属和状态；原子生成一套分享凭据 |
| 取消草稿 | POST /api/v1/transfers/{id}/cancel | 幂等失效并进入清理，不触及历史笔记 |
| 链接/码解析 | POST /api/v1/transfer-access | 凭据不放查询串；校验密码和登录策略，不消费名额 |
| 主动领取 | POST /api/v1/transfers/{id}/claims | 授权后原子分配名额与会话，领取操作 ID 唯一；重试返回同一会话 |
| 下载 | GET /api/v1/transfer-claims/{claimId}/items/{itemId}/download | 安全 Cookie 或等效凭据鉴权，不能仅凭 claimId；每次检查授权/到期/撤销/扫描与流量 |
| 完成领取 | POST /api/v1/transfer-claims/{claimId}/complete | 身份绑定、幂等完成；结束该会话，不重复扣名额 |
| 记录/状态 | 用户记录查询与凭据限定的状态查询/流 | 不产生领取副作用，不暴露跨用户或未领取正文 |

旧分享的 access/download 路由不得成为绕过新领取规则的通道：关联新传输时统一分派到新权限检查，旧分享才使用原行为。Cookie 采用独立名称/范围，绑定具体会话和需要时的登录身份；沿用现有跨站请求防护规范。

## 4. 状态与并发不变量

传输：上传中 → 已发布 → 已失效 → 清理完成；上传中可取消。名额耗尽是已发布传输的派生状态，不等于所有已领取会话立即失效。

领取：有效 → 主动完成 / 会话到期。重试不得再新建领取；已结束会话不能重新激活。丢失凭据不恢复已消费名额，界面说明领取窗口。

事务顺序：锁定传输/分享 → 检查失效与权限版本 → 查幂等操作 → 检查剩余名额 → 创建会话并增加计数 → 提交。统一锁顺序用于发布、撤销、领取与销毁，避免多路径竞态。

下载不等同领取。重试仍按既有流量规则计费/限额，领取计数不变。文件扫描未通过不得下载；扫描待定展示处理中，恶意文件阻断，不为了新 UX 放宽扫描边界。

最终销毁汇总方案仍待实施前整体批准：所有名额已消费且所有会话结束，或分享到期。文本主动查看消费一次名额后结束对应读取机会，最后一个名额消费后禁止新的读取；网络重试需要绑定同一操作的短暂响应恢复策略，不能以重试为由无限延长读取。该细节实施时补充精确测试契约。

销毁先提交终态并禁止新读取，再异步释放附件引用及清理正文。共享对象只有引用归零才物理删除；后台失败不会重新开放访问。已经传出的字节不能收回。对于正在进行的文件流，建议在会话/分享失效时取消流并关闭 Body，覆盖跨实例撤销传播；不能只在下载开始时检查一次就宣称即时停止。

## 5. 同步与前端建议

当前未发现可直接复用的推送通道，建议增加单向状态流，而非双向协同编辑系统。实现候选为 SSE；正式落位前核验服务超时、代理缓冲及心跳行为，不在本轮更改部署设施。

- 首次连接和重连读取数据库权威快照；变化提示只用于刷新，不把进程内事件当事实来源。
- MVP 可由有界、合并的数据库状态刷新驱动连接，避免依赖单实例广播；需限制连接数和查询频率，避免每连接全表轮询。
- 不承诺逐个补发断线期间事件，只保证恢复最新状态。心跳与最近成功同步时间驱动连接 UI；纯浏览器 online 不代表服务端连接成功。
- 同账号状态流与凭据限定的单传输状态流分别授权；失效后只发送必要终态并结束相关访问。
- 前端拆出发送区、上传队列、分享结果、领取页和状态 hook；App 保留路由/既有功能编排。
- 上传进度需真正的字节进度来源；建议在 API 客户端封装上传请求，不用定时器伪造进度。
- 文本保存后刷新其他设备；远端版本更新时保留本地脏草稿，提示刷新/重载，不静默覆盖。

## 6. 最小实施批次及验收

1. **传输/发布底座**：新增持久化和内存等价实现，多文件幂等与专属内容归属；用 HTTP 测试覆盖部分失败与发布竞争。
2. **取件与领取**：6 位码、限流、原子名额、30 分钟会话、旧路由隔离；真实 PostgreSQL 多连接测试防超领、防重扣和唯一性。
3. **销毁**：最终状态、引用安全释放、后台失败重试、失效下载及进行中流；验证旧内容不受无关传输影响。
4. **界面/文案**：游客和账号完整发送接收链，内联设置、真实参数、移动布局，保留老功能。
5. **状态同步**：跨设备与跨实例更新、凭据隔离、断线恢复和草稿保护；浏览器最终验收。

主要测试入口仍为已有 HTTP handler 集成测试。持久化并发沿用 PostgreSQL 跨连接测试，清理沿用 worker 任务/退避先例。基线与新增功能验证分别记录，缺失数据库或浏览器证据必须明确标记。

迁移只增不改历史文件；回滚不能简单降级到不认识领取权限的旧程序来服务新传输。上线前明确关闭新入口、保留授权检查与数据库恢复方案；代码回退不等于数据回退。

## 7. 尚需技术验证而非重开需求的问题

- 同步服务与现有 HTTP 超时的兼容；多实例状态查询成本和撤销流中断策略。
- 防猜码共享限流设施；具体阈值、码回收隔离时间、文件项数与领取名额的有限上限。
- 文本一次读取的网络失败恢复窗口，不增加永久可读副本。
- 新持久化接口如何接入现有事务与初始化；对象引用清理与传输终态的重试一致性。

这些是实现前验证项，不是已通过的结论；不得把当前设计稿或已发布 Issue 标签当作功能完成。
