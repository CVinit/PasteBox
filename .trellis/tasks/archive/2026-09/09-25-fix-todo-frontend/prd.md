# 按 TODO 修复前端问题

## Goal

按根目录 TODO 的 1–7 项顺序修复配置、会话和交互问题，完成自检与本地提交。
用户已授权在后端任务提交结束后继续按 TODO 修改，无需再次申请实施或提交确认。

## Requirements

1. Turnstile 的站点密钥和密钥输入位于注册安全配置附近，可编辑和保存，保留密钥留空不覆盖语义。
2. 首页探测已有会话；有效登录显示头像/用户信息与工作区入口。
3. 登录状态下访问 /register 或 /login 进入工作区，探测未完成时不展示可提交的注册表单。
4. 最近内容的操作按钮使用图标配合文字、悬停提示及必要的按下状态。
5. 后台保存结果在保存区域附近显示，并向辅助技术播报；失败保留草稿。
6. 套餐、价格、兑换码分组；每个套餐/价格独立保存，发送当前项目。运行配置按当前分组发送。兼容旧完整目录更新 API。
7. 页脚可点击链接与分组标题有清晰区别，支持键盘聚焦和窄屏。

## Approach

保持现有 React/CSS 结构与风格，不引入 UI 库。复用 typed API 客户端、服务端配置校验和持久化事务。
目录新增部分更新入口，以 ID 合并后使用原有整体验证与保存。服务配置继续沿用已有 secret patch 语义。
会话探测是页面启动行为；密码重置和邮件验证链接维持原流程。

- [x] TODO 3：有效会话打开注册/登录页进入 /app，不出现注册表单闪现。
- [x] TODO 4：桌面和手机都能识别最近内容的操作。
- [x] TODO 5：保存成功与失败均在操作附近可见。
- [x] TODO 6：分组显示、单项保存；保存一个套餐/价格不提交或覆盖别的草稿。
- [x] TODO 7：页脚链接有下划线/聚焦状态，不与静态文字混淆。
- [x] 类型检查、构建、后端变更测试、浏览器桌面/375px/多语言检查通过。
- [x] 更新 TODO、规范和任务记录，本地提交并归档。
