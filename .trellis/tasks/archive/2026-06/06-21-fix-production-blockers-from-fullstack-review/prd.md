# Fix Production Blockers From Fullstack Review

## Goal

Remove the two production blockers found in the fullstack review: shared attachment passwords must not be exposed in download URLs, and frontend dependency audit must fail the release gate when high severity advisories exist.

## Requirements

- Shared attachment downloads must not include share passwords in the URL query string.
- Password-protected share access must still allow users to download clean shared attachments after they have successfully opened the share.
- Release readiness must include a frontend high-severity dependency audit.
- Frontend dependencies must be upgraded or locked so `npm audit --audit-level=high` passes.
- Keep the fix narrowly scoped to the reviewed blockers.

## Acceptance Criteria

- [x] Shared attachment download links generated by the frontend contain no `password` query parameter.
- [x] Backend shared attachment download no longer reads passwords from `r.URL.Query()`.
- [x] Password-protected shared attachment downloads still work after successful share access.
- [x] `npm --prefix web --cache .cache/npm audit --audit-level=high` passes.
- [x] `make production-readiness` passes.
- [x] Browser smoke covers registration and paste creation, or a narrower smoke is documented if full browser smoke is not needed after backend/frontend tests.

## Definition of Done

- Relevant backend and frontend tests are added or updated.
- Typecheck/build/test gates pass.
- Temporary runtime resources are cleaned up.
- Remaining release risks, if any, are reported clearly.

## Technical Approach

Use a short-lived, HttpOnly share-access cookie set by the successful share access endpoint. The shared attachment download endpoint should validate either the request password passed through the existing access call or the cookie-derived grant, then serve a clean GET download URL without putting secrets into the URL.

For dependencies, apply the minimal lock/dependency update needed to clear high severity advisories, then wire `npm audit --audit-level=high` into the local production readiness script.

## Out of Scope

- Redesigning share tokens or password hashing.
- Changing paid plan limits, billing, object storage, or scanning behavior.
- Full external penetration testing.
- Real provider smoke against production Stripe/Epusdt/OAuth accounts.

## Technical Notes

- Review finding: `web/src/api.ts` generated shared attachment URLs with `?password=...`.
- Review finding: `internal/httpserver/server.go` read shared attachment passwords from URL query.
- Existing frontend API helper already sends unsafe requests with CSRF protection.
- Existing production gate is `make production-readiness`.

## Verification Notes

- Narrow smoke is covered by `TestAuthPasteUploadShareAndQuotaHTTPContracts`: register owner, create paste, upload attachment, mark scan clean, create password-protected share, reject `?password=` download, access the share, receive scoped HttpOnly grant cookie, and download through a clean shared attachment URL.
- `make build` now builds web assets, syncs them into `internal/httpserver/static`, then builds the Go binary so embedded local binaries do not carry stale frontend bundles.
