# PasteBox 产品 PRD

## 目标

构建一个面向海外/国际用户的云粘贴板/剪切板 SaaS。用户登录后可以在网页中快速保存、复制、上传、分享文本、图片和文件。所有用户数据默认私有隔离，内容都有明确过期时间，过期后立即不可访问并释放逻辑配额，物理文件由后台任务尽快删除和重试。产品通过会员等级控制活跃内容数量、存储空间、上传大小、有效期和流量，并支持 Stripe 订阅和 Epusdt/USDT 固定时长会员订单。

产品名定为 PasteBox。仓库名、Go module 名、包名、CLI 二进制名统一采用小写 `pastebox`。当前规划任务目录可保留历史名称，不影响后续代码初始化。

## 已确认定位

- 产品面向公开用户提供服务，不是个人自用工具。
- 首发按海外/国际版 SaaS 设计，可以提供中文界面，但不优先承诺中国大陆访问质量、ICP备案、国内支付、短信登录。
- MVP 是云剪切板和临时文件中转服务，不做公开内容社区。
- 内容默认私有；用户可以主动生成受控分享链接。
- MVP 不做团队/组织空间，只做个人账号，但权限和账单模型保留后续扩展点。
- MVP 不允许游客创建或上传内容；匿名用户只能访问允许匿名访问的分享链接。

## MVP 范围

### 用户与登录

- 支持邮箱 magic link 登录。
- 支持 Google OAuth 登录。
- 支持邮箱 + 密码登录，不做独立用户名登录。
- 用户可设置显示名，但登录主键使用邮箱。
- 密码使用 Argon2id 哈希。
- 注册和账号恢复必须依赖邮箱验证。
- 支持忘记密码邮件重置。
- 登录失败需要限流。
- Web 登录态使用 HttpOnly Secure Cookie。
- 支持多设备登录和退出所有设备。
- 管理员账号后续应强制 2FA；普通用户 MVP 不强制 2FA。

### Paste 内容模型

- 一条 paste 可以包含一段文本和多个附件。
- 附件可以是图片或普通文件；图片是文件的一种，但前端提供图片预览。
- 每条 paste 可设置可选标题。
- 每条 paste 可设置标签。
- 每条 paste 有明确 `expires_at`。
- 每条 paste 属于一个用户，默认只对所有者可见。
- 每条 paste 的文本、附件、分享、扫描、删除状态必须可追踪。
- 文本内容大小按会员等级单独限制，同时计入单条 paste 总大小和活跃存储配额。
- 超过文本上限时，前端提示用户作为 `.txt` 文件附件上传。
- 文本大小必须由后端按字节强校验，不能只依赖前端限制。

### 前端主体验

- 主界面采用时间线/收件箱式 paste 列表，不做多级目录。
- 顶部提供快速新建 paste 的文本框和文件入口。
- 支持网页聚焦时通过 `Ctrl/Cmd+V` 粘贴文本、图片、文件。
- 支持拖拽上传文件。
- 支持点击按钮将文本复制到本机剪贴板。
- 不做浏览器后台监听剪贴板。
- 不做桌面常驻同步客户端。
- 不做跨设备自动覆盖系统剪贴板。
- 列表按时间倒序展示 paste。
- 每条 paste 展示标题、文本摘要、附件数、大小、过期倒计时、分享状态、扫描状态。
- 支持标签、收藏/置顶、搜索和过滤。
- 过滤至少包括文本、图片、文件、即将过期、已分享。

### 移动端与 PWA

- MVP 做响应式 Web + PWA 安装，不做 iOS/Android 原生 App。
- 手机浏览器必须支持登录、查看、复制文本、上传照片/文件、分享、删除、续期。
- 支持 PWA manifest，允许添加到主屏幕。
- 不要求离线可用。
- 使用系统文件选择器。
- 如果浏览器支持，相机/拍照上传可以通过系统能力自然可用。

### 搜索

- MVP 做用户私有搜索，不做公开搜索、不做跨用户搜索。
- 用户可按标题、文本内容、文件名搜索自己的未删除内容。
- 过期或删除内容不出现在普通搜索结果。
- 分享链接访问者不能搜索创建者的其他内容。
- 第一版可使用 PostgreSQL full-text 或简单 `ILIKE`；数据量上来后再评估专门搜索引擎。

### 分享

- MVP 支持受控分享链接。
- 默认分享链接允许匿名访问。
- 分享创建者可以设置分享密码。
- 分享创建者可以设置最大访问次数或下载次数。
- 访问次数和下载次数必须分开计数，也允许分开限制。
- 访问次数：打开分享页并通过密码或登录校验后计 1 次。
- 下载次数：每个附件实际开始下载计 1 次。
- 文本复制不算下载，但算访问。
- 达到访问次数或下载次数上限后，分享链接失效，但 paste 本体仍保留。
- 分享创建者可以设置仅登录用户可访问。
- 分享创建者可以随时撤销分享链接。
- 分享链接可单独提前过期。
- 分享链接的过期时间不能超过 paste 本体过期时间。
- paste 一旦过期，所有分享立即失效。
- 如果用户延长 paste 过期时间，已有分享链接不自动延长，除非用户手动修改分享设置。
- 指定邮箱收件人限制不进 MVP，作为后续功能。

### 有效期与续期

- 所有文字、文件、图片都必须有固定失效时间。
- 未过期 paste 可以手动延长。
- 已过期 paste 不可恢复，因为业务上已不可访问，物理文件可能已被删除。
- 延长后的 `expires_at` 不能超过当前会员等级允许的最长有效期。
- 延长时重新检查当前会员等级、活跃存储、活跃数量和风控状态。
- 免费用户可以延长到免费层上限，但不能无限续命。

### 过期删除语义

- 到期后必须立即不可访问。
- 读取、下载、分享访问都必须检查 `expires_at`，过期返回 404 或 410。
- 过期后立即释放逻辑配额。
- 后台清理任务周期性扫描过期记录，删除对象存储文件。
- 物理删除成功后更新状态为 `deleted`。
- 对象存储删除失败时进入重试队列，不影响用户可见状态。
- 管理后台必须能查看 `pending_delete` 积压和失败原因。

## 会员与配额

### 配额模型

配额必须组合限制，不能只限制单次上传大小：

- 活跃 paste 数量。
- 活跃总存储容量。
- 单条 paste 总大小。
- 单条文本大小。
- 单文件大小。
- 单条附件数量。
- 最长有效期。
- 每日上传流量。
- 每日分享下载流量。

活跃资源指未过期、未删除、仍占用户业务配额的资源。过期后立即不计入活跃配额。

每日上传流量和每日分享下载流量统一按 UTC 自然日统计。后端、Redis key、DB 汇总和支付/风控对账都使用 UTC 日窗口；前端可以按用户本地时间展示距离重置的剩余时间。

### 首发会员等级

会员额度和价格必须配置化，不能散落在前后端常量里。前端价格页、后端 enforcement、支付下单都应来自同一份 plan 配置或接口。

| 等级 | 活跃 paste | 活跃存储 | 单条文本 | 单文件 | 单条总大小 | 附件/条 | 最长有效期 | 日上传 | 日分享下载 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Free | 20 | 500 MB | 256 KB | 25 MB | 50 MB | 5 | 24 小时 | 1 GB | 2 GB |
| Plus | 500 | 50 GB | 2 MB | 250 MB | 1 GB | 20 | 30 天 | 20 GB | 100 GB |
| Pro | 5000 | 500 GB | 10 MB | 2 GB | 5 GB | 100 | 180 天 | 200 GB | 1 TB |

### 降级和到期

- 会员降级或到期后，已有未过期 paste 不立即删除，也不强制缩短有效期。
- 新建、上传、续期等新操作按当前等级限制。
- 如果用户活跃数量或容量超过新等级限制，则进入超额只读状态。
- 超额只读状态下，用户不能新建、上传、延长有效期。
- 用户可以删除内容或等待过期来恢复到配额内。
- 现有分享链接仍按原有效期可访问，除非内容过期、用户主动撤销或触发风控封禁。
- 严重滥用账号可由管理后台冻结或强制下线内容。

## 支付与会员开通

### 支付方式

- 第一版接 Stripe 订阅。
- 第一版也支持或预留 Epusdt/USDT 收款方案。
- 管理员后台支持手动调整会员等级和到期时间。
- Plus/Pro 的价格、币种、月付/年付周期、折扣、是否展示、是否允许购买，都必须由后台配置。
- 代码里不允许硬编码会员价格。
- 前端价格页、Stripe Checkout、Epusdt/USDT 下单金额必须读取后台启用中的 plan/price 配置。
- 后台修改价格不应影响已支付订单的历史金额记录。

### Stripe

- Stripe 用于 Plus/Pro 的月付和年付订阅。
- 使用 Stripe Checkout 和 Customer Portal。
- 通过 Stripe webhook 处理订阅创建、续费、取消、付款失败、退款。
- 本地会员状态以本地 `subscriptions` 表为准，由 Stripe webhook 驱动更新。
- Webhook 处理必须幂等。

### Epusdt/USDT

- Epusdt/USDT 不做自动续费。
- Epusdt/USDT 首发只启用 USDT-TRC20。
- 支付模型保留多链多币种配置能力，后续可按后台配置开启 USDT-ERC20、USDT-BEP20 等其他链。
- 用户选择 Plus/Pro 和购买时长后生成一次性订单。
- 到账后开通对应天数。
- 订单超时未支付自动关闭。
- 多付或少付不自动乱处理，进入人工审核或按配置规则处理。
- 不做加密货币自动退款，后台人工处理。
- 建模上应区分 `Subscription` 和 `OneTimeMembershipOrder`。

### 管理员调整

- 管理员可手动调整会员等级、到期时间和覆盖状态。
- 管理员手动调整必须有审计日志。
- 手动 override 应支持过期时间。

## 文件存储

### 存储抽象

- 存储层按 S3 兼容对象存储抽象设计。
- 开发环境和单机自部署默认使用 MinIO。
- 正式公网生产环境优先使用托管 S3 兼容对象存储，例如 Cloudflare R2、Backblaze B2 或 AWS S3。
- 代码只依赖 S3 兼容接口，不把业务逻辑绑定到某个具体存储供应商。
- 本地文件适配器只作为开发或测试辅助，不作为推荐生产形态。
- 后续可在 AWS S3、Cloudflare R2、Backblaze B2、MinIO 等 S3 兼容后端之间切换。
- 文件内容不进入数据库。
- 数据库保存对象 key、size、sha256、状态、过期时间等元数据。
- 对象存储 bucket 必须私有。
- 对象 key 不可猜测。
- 下载必须经过后端鉴权或短期签名 URL。

### 去重

- MVP 只做同一用户内的内容去重，不做跨用户去重。
- 不做跨用户去重是为了避免通过秒传、占用变化等侧信道推测其他用户是否存过同一文件。
- 用户内可以基于 sha256 复用对象引用。
- 会员配额按每个 paste 引用的逻辑大小计入，避免靠重复引用绕过产品边界。
- 物理删除按引用计数为 0 删除对象。

### 上传链路

- MVP 上传先走后端中转。
- 上传前后端检查会员配额、大小限制、附件数量和风控状态。
- 上传中计算 sha256。
- 后端负责对象写入、落库和失败清理。
- 设计上保留 `UploadSession` 概念，后续可以升级为浏览器直传 S3 multipart upload。

## 安全、隐私与风控

### 加密与隔离

- MVP 不做端到端加密。
- 服务端必须做严格权限隔离和静态加密能力。
- 文本默认存数据库，可选压缩，受大小限制。
- 文件存对象存储。
- 数据库保存 sha256、mime、大小等元数据。
- 后续可增加客户端加密 paste 高级隐私模式；该模式功能可受限。

### 内容安全

- MVP 必须包含最低限度风控。
- 上传文件类型黑名单和可执行文件风险提示。
- MIME 嗅探，不只相信扩展名。
- 单用户/IP 上传、下载、分享访问限流。
- 分享链接访问异常时可自动冻结。
- 提供举报入口和后台下架能力。
- 集成 ClamAV 异步病毒扫描。
- 禁止 HTML/SVG 直接内联渲染，避免 XSS。
- 文本预览必须严格转义。
- 图片预览必须使用安全响应头，不能执行脚本内容。
- 不在 MVP 做复杂版权识别、AI 黄暴恐审核、全文自动内容审查和自动封号。

### 扫描状态规则

- 扫描中的文件，所有者可见且可下载，但提示未完成扫描。
- 匿名分享和非所有者访问必须等扫描完成且状态为 clean 后才能下载。
- 扫描失败进入 `scan_failed`，默认不允许公开下载，管理员可放行或重扫。
- 检测为恶意时文件冻结，所有下载禁止，用户和管理员可见原因。
- 文本内容不走 ClamAV，但仍必须做 XSS 转义和滥用限流。

## 管理后台

MVP 必须有最小可用 admin 后台：

- 用户列表、搜索、查看用户状态、会员、配额。
- 手动调整会员等级、到期时间、冻结/解冻账号。
- paste/附件查询：按用户、hash、文件名、状态、时间。
- 下架 paste、冻结附件、撤销分享链接。
- 举报处理队列。
- 扫描失败和删除失败重试队列。
- 支付订单和 webhook 事件查看、重放。
- 审计日志：记录谁在后台做了什么。
- 基础指标：活跃用户、存储占用、上传/下载流量、任务积压。

MVP 不做复杂后台权限系统，只区分 `admin` 和普通用户；但所有 admin 操作必须写审计日志。

### 管理员初始化

- 首个管理员只能通过部署时 CLI 命令创建，例如 `pastebox admin create --email ...`。
- 不允许通过网页公开注册成为管理员。
- 已存在管理员后，新增管理员必须由现有管理员在后台创建，或通过受保护 CLI 执行。
- 普通注册流程永远不能把用户提升为 admin。
- 管理员创建、禁用、权限变更都必须写审计日志。

## 邮件与通知

MVP 只做关键事务邮件，不做营销邮件和过期提醒。

必须发送：

- magic link 登录。
- 邮箱验证。
- 密码重置。
- 订阅或订单支付成功。
- 付款失败或订阅取消。
- 账号安全提醒：新设备登录、密码修改。
- 管理员强制冻结或下架通知，可配置是否发送。

邮件服务应抽象为 `Mailer`。开发环境可打印到日志或使用 Mailpit。生产默认使用 Resend，保留 Postmark 和 SES 适配器扩展点，后续可切换。

## 数据导出与账号删除

- 用户可导出自己的 paste 元数据和文本内容为 JSON/ZIP。
- 文件附件可按导出任务生成临时 ZIP，但受大小限制。
- 超大导出后续再做分卷。
- 用户可申请删除账号。
- 删除账号后立即停用登录、撤销分享、标记所有内容待删除。
- 物理文件进入后台删除队列。
- 支付、审计、风控日志按合规和财务需要保留最小记录，不随账号删除完全抹除。
- 删除账号设置 7 天冷静期，可取消。
- 真正执行后不可恢复。

## 多语言

- 第一版做中英双语。
- 英文作为 fallback。
- 默认语言根据浏览器选择。
- 用户可手动切换语言。
- 前端文案走 i18n。
- 邮件模板支持英文和中文。
- 后台也应支持中文和英文。
- 不做更多语言。

## 技术架构

### 首发技术栈

- 后端：Go。
- HTTP 框架：Chi。
- 数据库：PostgreSQL。
- 查询层：sqlc。
- 迁移：Goose。
- DB driver：pgx。
- 缓存、限流、队列依赖：Redis。
- 后台任务队列：Asynq + Redis。
- 对象存储：S3 compatible，单机可用 MinIO。
- 病毒扫描：ClamAV daemon。
- 前端：React + TypeScript + Vite。
- UI：Tailwind + shadcn/ui。
- 部署：Docker Compose 首发。
- 反向代理：Nginx。

### 架构形态

- MVP 采用模块化单体，不拆微服务。
- 后续可以把 scanner、cleanup、大文件上传 worker 独立出去。

建议模块：

- `auth`：登录、会话、OAuth、magic link、密码。
- `users`：用户资料、状态、管理员操作。
- `billing`：会员、Stripe、Epusdt、订单、权益。
- `pastes`：paste 生命周期、文本、标签、搜索。
- `attachments`：上传、对象存储、去重、下载。
- `shares`：分享链接、密码、次数、访问日志。
- `quota`：配额计算、日流量、超额状态。
- `scanner`：ClamAV 队列、扫描状态。
- `cleanup`：过期、对象删除、重试。
- `admin`：后台、审计、风控操作。

### 数据库与事务

- PostgreSQL 是核心事实来源。
- Redis 不作为核心事实库。
- 事务使用显式 `pgx.Tx`。
- 配额扣减、分享次数、引用计数、订单状态必须使用强一致 SQL 和事务控制。
- 关键并发可使用 `SELECT ... FOR UPDATE` 或原子 `UPDATE ... WHERE`。
- 重要索引应覆盖 `user_id + status + expires_at`、`share_token_hash`、`object_key`、`scan_status` 等访问路径。

### Redis 使用边界

Redis 可用于：

- 会话索引或撤销列表。
- magic link / password reset 短期 token。
- IP/用户限流计数。
- 每日上传/下载流量快速计数，并由 DB 事件表或定期落账补偿。
- Asynq worker 队列。
- 分布式锁和任务幂等辅助。

Redis 不用于：

- 用户会员最终状态。
- paste 元数据。
- 文件引用计数。
- 订单最终状态。
- 配额最终账本。

### 队列

- 后台任务使用 Asynq + Redis。
- `critical` 队列：支付 webhook、会员状态同步。
- `default` 队列：邮件、扫描任务。
- `low` 队列：过期清理、对象删除重试、统计汇总。
- 所有任务 handler 必须幂等。
- 数据最终状态仍落 PostgreSQL。

### API

- MVP 只承诺内部 Web API，不公开稳定第三方 API 合约。
- Web 前端使用 `/api/v1/...`。
- Cookie session 认证为主。
- 个人 API Token 表和模型可预留。
- 如果 MVP 做个人 API Token，必须支持作用域、过期时间、最后使用时间、撤销。
- CLI、浏览器扩展和公开稳定 API 放后续版本。
- OpenAPI 文档可以内部生成，但不对外承诺兼容。

## 部署、备份与灾备

### 首发部署

- 首发采用单服务器 Docker Compose 部署。
- Nginx 作为统一入口反代。
- 生产推荐模式是 Cloudflare 前置 + Nginx 源站，获得 CDN、基础 DDoS 防护、WAF 和证书管理便利。
- 部署也必须支持 Nginx 直连公网 + ACME/certbot，不强依赖 Cloudflare。
- Cloudflare 只是边缘层，Nginx 仍是源站入口，方便后续多机部署。
- 后端未来多实例时通过 Nginx upstream 承载。
- 上传大小、超时、缓冲、限流在 Nginx 明确配置。
- 后续 K8s 可迁移到 Nginx Ingress 或保留边缘 Nginx。

### 备份与恢复

- 单机部署也必须从第一天有备份。
- PostgreSQL 每日全量备份 + WAL/增量备份。
- 备份保留至少支持 7/30 天策略。
- MinIO 或本地对象存储数据必须定期快照或同步到远端 S3/R2/B2。
- Redis 不作为事实库，可不做强备份。
- 配置和密钥分离备份。
- 提供恢复演练脚本或至少文档化恢复步骤。
- MVP 不承诺多活。
- 首发灾备目标：RPO 24 小时以内，RTO 手工恢复 4 小时以内。

### 观测和告警

MVP 必须至少覆盖：

- 磁盘容量。
- PostgreSQL 可用性和备份失败。
- Redis 可用性。
- Asynq 队列积压。
- 删除失败积压。
- 扫描失败积压。
- 支付 webhook 失败。
- 上传/下载错误率。

## 非目标

MVP 明确不做：

- 中国大陆首发合规链路，包括 ICP、国内支付、短信登录。
- 公开内容社区、公开搜索、推荐、评论。
- 团队/组织空间。
- 游客创建或上传。
- 多级目录文件管理器。
- 浏览器后台剪贴板监听。
- 桌面常驻客户端。
- iOS/Android 原生 App。
- 端到端加密。
- 跨用户文件去重。
- 复杂 AI 内容审核。
- Stripe 以外的自动续费渠道。
- Epusdt/USDT 自动续费。
- 稳定公开第三方 API。
- 多活或低 RPO/RTO 高可用承诺。
